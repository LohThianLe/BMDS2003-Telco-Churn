## Data Preprocessing

This section explains how the raw dataset (`data/Telco_Cusomer_Churn.csv`) was cleaned before modeling, and why. Cleaned output files (`clean_X_train.csv`, `clean_X_test.csv`, `clean_y_train.csv`, `clean_y_test.csv`, plus scaled versions) are generated by running `preprocessing.py`.

### Steps and reasoning

1. **Dropped `customerID`**
   Just an ID number, doesn't help predict churn, would only confuse the model.

2. **Fixed `TotalCharges` (11 blank values → 0)**
   Those 11 customers all had `tenure = 0` — brand new sign-ups who haven't been billed yet. A blank there means "$0 so far," not "unknown," so we filled it with `0` instead of guessing or deleting rows.

3. **Collapsed "No internet service" / "No phone service" → "No"**
   Columns like `OnlineSecurity` had a 3rd option that only exists because the customer has no internet at all — info already captured in another column. Keeping it separate just duplicates the same fact and can confuse some models, so we simplified it to plain `"No"`.

4. **Converted Yes/No columns to 1/0**
   Models can't read text like "Yes"/"No" — they need numbers. Simple, direct conversion, no information lost.

5. **One-hot encoded `Contract`, `InternetService`, `PaymentMethod`**
   These have 3–4 categories with no natural ranking (e.g. "Fiber optic" isn't "more" than "DSL"). One-hot encoding avoids the model wrongly assuming one category is mathematically bigger/better than another. Chosen over simple number-labeling since we hadn't picked our models yet — one-hot works safely regardless of which models get chosen.

6. **Dropped one column per one-hot group (`drop_first=True`)**
   If a customer isn't DSL and isn't Fiber, they must be "No internet" — keeping all 3 columns is redundant. Dropping one avoids feeding the model duplicate information, which specifically helps Logistic Regression stay accurate and interpretable.

7. **70/30 train-test split, fixed random seed (`random_state=42`)**
   70% of customers used to train, 30% held back to test fairly on unseen data. The fixed seed ensures everyone on the team gets the same split when running the code, so results are comparable across models.

8. **Checked for outliers — none found worth removing**
   Reviewed `tenure`, `MonthlyCharges`, and `TotalCharges` for extreme/unrealistic values. Nothing stood out, so no rows were removed for this reason.

9. **Produced a scaled version of the numeric columns**
   Models like KNN and Logistic Regression can be skewed if one number (e.g. `TotalCharges`, up to $8,684) overshadows a small one (e.g. a 0/1 column). Scaling puts all numeric columns on the same footing. Tree-based models don't need this, so both scaled and unscaled versions are provided — use whichever fits your model.
